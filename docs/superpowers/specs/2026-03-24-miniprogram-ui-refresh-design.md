# 小程序界面优化设计

日期：2026-03-24

## 背景

当前小程序已具备首页、参数查询、模板库、个人中心、轻咨询等页面，但界面存在以下问题：

- 首页以同权重卡片堆叠为主，缺少主次层级，首屏不够像工具入口
- 参数查询页信息结构偏散，重点指标、筛选条件、数值展示没有形成稳定的扫描路径
- 模板库沿用大卡片陈列方式，更像商品卡片墙，不像专业资料目录
- 全局颜色、边框、强调方式不够统一，页面之间缺少一致的产品语言

## 目标

- 将核心页面统一为“工业工作台”风格，强化专业、克制、可信的工具感
- 优先提升信息扫描效率，让用户更快完成“查参数、找模板、发咨询”
- 统一视觉系统，减少无效装饰和低信息密度卡片
- 在不改变核心业务路径的前提下完成界面升级

## 范围

本次设计覆盖以下 3 个核心页面：

- `frontend/src/pages/home/index.tsx`
- `frontend/src/pages/parameter/index.tsx`
- `frontend/src/pages/template/index.tsx`

本次不包含业务接口、字段定义、页面路由、详情页功能扩展。

## 设计方向

选定方向：A. 工业工作台

视觉基调：

- 深钢蓝作为主色，冷灰和浅雾白作为背景层级
- 弱化大面积营销式卡片，改用分区、列表、标签、数据读数构建层级
- 保留少量强调色，仅用于重点操作、购买状态、咨询入口
- 交互反馈以按压态、选中态、筛选态为主，不引入花哨动效

## 页面设计

### 1. 首页

首页改为工作台入口，不再保留四张同权重功能卡。

结构：

1. 顶部品牌区
2. 主操作区
3. 热门材料索引
4. 最近更新
5. 咨询与免责声明

具体设计：

- 顶部品牌区展示产品名、副标题和搜索入口，形成稳定首屏锚点
- 主操作区只保留 3 个高频入口：参数速查、模板库、轻咨询
- “参数速查”作为最强主入口，占更大视觉权重
- 热门材料索引改为紧凑标签或横向列表，支持快速跳转参数页
- 最近更新改为时间线式或轻量列表，降低块状卡片数量
- 底部咨询入口作为明确动作按钮，不与信息列表混在一起

预期结果：

- 用户进入首页后能在一屏内判断主入口
- 首页从“功能卡片集合”转为“任务工作台”

### 2. 参数查询页

参数查询页改为数据浏览页，目标是让用户快速筛选并扫描关键参数。

结构：

1. 顶部标题和返回区
2. 搜索框
3. 分类切换条
4. 参数列表

具体设计：

- 顶部采用统一的深色标题区，但文字与控件保持高对比，避免当前黑字压在主色背景上的问题
- 搜索框独立成稳定输入区，不与其他按钮混杂
- 分类切换条做成更明确的筛选条，选中态强化，未选中态弱化
- 参数列表统一为“左信息 + 右数值”的双区结构
- 左侧展示参数名和简短指标说明
- 右侧展示数值和单位，数值是最强视觉焦点
- 重点参数不再整卡高亮，改为左侧标识线、重点标签或数值强调，减少视觉噪音
- 空状态、加载态保持统一样式

预期结果：

- 用户能更快区分“参数名称”“参数意义”“参数数值”
- 高频重要参数更醒目，但页面整体更稳

### 3. 模板库页

模板库改为资源目录页，不再走重卡片商品墙路径。

结构：

1. 顶部标题和筛选入口
2. 分类切换条
3. 模板目录列表

具体设计：

- 顶部结构与参数查询页保持一致，形成统一产品语言
- 筛选入口强调“全部 / 免费 / 付费”状态，而不是做成弱感知按钮
- 模板条目改为目录式列表，单条信息包括：
  - 模板名
  - 适用场景说明
  - 状态标签或价格
  - 操作按钮
- 保留封面占位但缩小视觉比重，避免大面积无意义占图
- 免费与付费模板通过状态色和文案区分，但不引入过多色彩

预期结果：

- 模板库更像专业资源中心
- 浏览效率和购买决策效率都会提升

## 视觉系统

### 色彩

- 主色：深钢蓝，用于导航区、重点选中态、主要入口
- 背景：冷灰白和浅层白，拉开页面结构层级
- 强调色：仅用于咨询、价格、重点行动
- 辅助色：成功、警示、空状态沿现有语义保留，但降低使用频率

### 组件基调

- 卡片默认弱化，只有在承载操作时才保留明显容器感
- 边框比阴影更重要，以细边线和浅底色分区
- 圆角适度统一，不走强圆润风格
- 标题、说明、数值三层字重清晰区分

### 动效

- 保留按压反馈、Tab 切换、按钮选中态
- 不增加复杂转场和装饰性动画

## 数据与交互流

- 首页主入口点击后仍沿用现有导航逻辑，不改变页面跳转路径
- 首页热门材料索引直接跳到参数查询页，并默认定位到对应品类
- 参数查询页搜索仍基于当前分类过滤
- 模板库筛选仍基于“全部 / 免费 / 付费”三种状态

## 风险与兼容性

- 当前页面样式有部分主色背景下的黑字问题，改版时需要统一修正
- 当前页面大量依赖通用 `.tabs`、`.list-item`、`.card` 风格，改造时要避免无意影响其他页面
- Taro/微信小程序环境下应避免依赖 Web 端专属高级样式能力

## 实施建议

建议拆为以下实现步骤：

1. 统一全局视觉变量和基础组件样式
2. 重构首页结构与样式
3. 重构参数查询页结构与样式
4. 重构模板库页结构与样式
5. 补充基础自测，验证三页视觉与交互一致性

## 测试与验收

验收标准：

- 三个页面的视觉语言统一，首屏层级明确
- 首页首屏能清楚表达主任务入口
- 参数查询页支持快速搜索、分类切换、重点参数识别
- 模板库页支持快速筛选、浏览、区分免费与付费
- 小程序端在常见移动尺寸下没有明显溢出、遮挡、对比度问题

建议验证：

- `npm --prefix frontend run build:weapp`
- 微信开发者工具预览三个页面
- 手动验证点击态、空状态、长文案换行和横向滚动表现
