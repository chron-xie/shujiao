# 小程序界面优化设计

日期：2026-03-24

## 背景

当前小程序已具备首页、参数查询、模板库、个人中心、轻咨询等页面，但界面存在以下问题：

- 首页以同权重卡片堆叠为主，缺少主次层级，首屏不够像工具入口
- 参数查询页信息结构偏散，重点指标、筛选条件、数值展示没有形成稳定的扫描路径
- 模板库沿用大卡片陈列方式，更像商品卡片墙，不像专业资料目录
- 全局颜色、边框、强调方式不够统一，页面之间缺少一致的产品语言

## 目标

- 将核心页面统一为“工业工作台”风格，强化专业、克制、可信的工具感
- 优先提升信息扫描效率，让用户更快完成“查参数、找模板、发咨询”
- 统一视觉系统，减少无效装饰和低信息密度卡片
- 在不改变核心业务路径的前提下完成界面升级

## 范围

本次设计覆盖以下 3 个核心页面：

- `frontend/src/pages/home/index.tsx`
- `frontend/src/pages/parameter/index.tsx`
- `frontend/src/pages/template/index.tsx`

本次不包含业务接口、字段定义、页面路由、详情页功能扩展。

## 设计方向

选定方向：A. 工业工作台

视觉基调：

- 深钢蓝作为主色，冷灰和浅雾白作为背景层级
- 弱化大面积营销式卡片，改用分区、列表、标签、数据读数构建层级
- 保留少量强调色，仅用于重点操作、购买状态、咨询入口
- 交互反馈以按压态、选中态、筛选态为主，不引入花哨动效

## 页面设计

### 1. 首页

首页改为工作台入口，不再保留四张同权重功能卡。

结构：

1. 顶部品牌区
2. 主操作区
3. 热门材料索引
4. 最近更新
5. 咨询与免责声明

具体设计：

- 顶部品牌区展示产品名、副标题和搜索入口，形成稳定首屏锚点
- 主操作区只保留 3 个高频入口：参数速查、模板库、轻咨询
- “参数速查”作为最强主入口，占更大视觉权重
- 现有 `实拍规范 SOP` 不删除业务入口，调整为首页次级入口，放入“常用资源”轻量列表中，保留现有点击行为；若当前版本无可达页面，则继续展示“开发中”反馈
- 热门材料索引改为紧凑标签或横向列表，支持快速跳转参数页
- 最近更新改为时间线式或轻量列表，降低块状卡片数量
- 最近更新区块本期直接复用首页现有 `updates` 静态数据，并按日期新到旧展示；若未来数据为空，则整个区块隐藏，不渲染空占位
- 底部咨询入口作为明确动作按钮，不与信息列表混在一起

预期结果：

- 用户进入首页后能在一屏内判断主入口
- 首页从“功能卡片集合”转为“任务工作台”

### 2. 参数查询页

参数查询页改为数据浏览页，目标是让用户快速筛选并扫描关键参数。

结构：

1. 顶部标题区
2. 搜索框
3. 分类切换条
4. 参数列表

具体设计：

- 顶部采用统一的深色标题区，但文字与控件保持高对比，避免当前黑字压在主色背景上的问题
- 由于参数查询页是 tabBar 页面，默认从 tabBar 进入时不展示自定义返回按钮，只展示标题与搜索区；仅在未来存在非 tabBar 深链进入方案时，才允许补充返回控制
- 搜索框独立成稳定输入区，不与其他按钮混杂
- 分类切换条做成更明确的筛选条，选中态强化，未选中态弱化
- 参数列表统一为“左信息 + 右数值”的双区结构
- 左侧默认展示参数名；若现有数据存在可复用说明字段则展示第二行说明，否则不生成占位说明文案
- 右侧展示数值和单位，数值是最强视觉焦点
- 重点参数不再整卡高亮，改为左侧标识线、重点标签或数值强调，减少视觉噪音
- 重点参数的判定本期严格复用现有数据中的 `is_highlight` 字段，不新增名单和业务规则；仅当 `is_highlight === true` 时渲染重点样式
- 空状态、加载态保持统一样式

预期结果：

- 用户能更快区分“参数名称”“参数意义”“参数数值”
- 高频重要参数更醒目，但页面整体更稳

### 3. 模板库页

模板库改为资源目录页，不再走重卡片商品墙路径。

结构：

1. 顶部标题区
2. 分类切换条
3. 价格筛选条
4. 模板目录列表

具体设计：

- 顶部结构与参数查询页保持一致，形成统一产品语言
- 由于模板库页也是 tabBar 页面，默认从 tabBar 进入时不展示自定义返回按钮
- “全部 / 免费 / 付费”从当前 ActionSheet 改为页面内常驻分段筛选条，放在分类切换条下方，保证当前筛选状态始终可见
- 模板条目改为目录式列表，单条信息包括：
  - 模板名
  - 适用场景说明
  - 状态标签或价格
  - 操作按钮
- 保留封面占位但缩小视觉比重，避免大面积无意义占图
- 免费与付费模板通过状态色和文案区分，但不引入过多色彩
- 整行区域保持可点击，点击后进入详情页；右侧操作按钮与整行点击保持相同行为，不设计独立分叉动作，避免重复交互心智
- 封面占位调整为小尺寸缩略区，固定 4:3 比例，宽度控制在单行内容区约 22% 到 26%

预期结果：

- 模板库更像专业资源中心
- 浏览效率和购买决策效率都会提升

## 视觉系统

### 色彩

- 主色：`#1F4D66`，用于导航区、重点选中态、主要入口
- 主色加深：`#16384C`，用于按压态和深色标题区
- 背景：`#EEF3F6` 与 `#FFFFFF`，拉开页面结构层级
- 分割线：`#D7E0E6`
- 主文字：`#1C2731`
- 次文字：`#5F6B76`
- 弱文字：`#8A97A3`
- 强调色：`#F28A2E`，仅用于咨询、价格、重点行动
- 辅助色：成功、警示、空状态沿现有语义保留，但降低使用频率

### 组件基调

- 卡片默认弱化，只有在承载操作时才保留明显容器感
- 边框比阴影更重要，以细边线和浅底色分区
- 圆角统一为 `16rpx` 到 `20rpx`，不走强圆润风格
- 标题、说明、数值三层字重清晰区分
- 页面主标题建议 `40rpx/700`
- 分区标题建议 `28rpx/600`
- 列表主信息建议 `30rpx/600`
- 辅助说明建议 `24rpx/400`
- 核心数值建议 `34rpx/700`
- 页面横向安全边距建议 `24rpx` 到 `32rpx`
- 主要点击区域最小高度不低于 `88rpx`
- 深色背景上的文字与控件需满足不低于 4.5:1 的对比度目标

### 动效

- 保留按压反馈、Tab 切换、按钮选中态
- 不增加复杂转场和装饰性动画

## 数据与交互流

- 首页主入口点击后仍沿用现有导航逻辑，不改变页面跳转路径
- 首页热门材料索引直接跳到参数查询页，并默认定位到对应品类
- 热门材料与现有 tab 的映射在本期限定为：
  - `FR-4`、`G11` -> `玻纤板(FR-4/G11)`
  - `PI` -> `PI板`
  - `PEEK`、`PPS`、`PEI` -> `特种塑胶通用`
- 首页到参数页的联动采用 `Taro.setStorageSync('parameterCategory', value)` + `switchTab`；参数页 `useDidShow` 或等效进入时机读取该值并设置 `activeTab`
- 若索引标签无法命中 3 个现有分类，则回退到当前默认分类，不新增路由参数和接口字段
- 参数查询页搜索仍基于当前分类过滤
- 模板库筛选仍基于“全部 / 免费 / 付费”三种状态

## 风险与兼容性

- 当前页面样式有部分主色背景下的黑字问题，改版时需要统一修正
- 当前页面大量依赖通用 `.tabs`、`.list-item`、`.card` 风格，改造时要避免无意影响其他页面
- Taro/微信小程序环境下应避免依赖 Web 端专属高级样式能力
- 全局层面只允许调整设计 token，例如颜色、文字、圆角、间距变量；结构性改造必须优先使用页面级 class，避免误伤未纳入本次范围的页面

## 实施建议

建议拆为以下实现步骤：

1. 统一全局视觉变量和基础组件样式
2. 重构首页结构与样式
3. 重构参数查询页结构与样式
4. 重构模板库页结构与样式
5. 补充基础自测，验证三页视觉与交互一致性

## 测试与验收

验收标准：

- 三个页面的视觉语言统一，首屏层级明确
- 以 `390px` 宽度等效移动视口为基准，首页首屏需完整展示品牌区和至少 2 个主入口，用户无需滚动即可判断主任务入口
- 参数查询页支持快速搜索、分类切换、重点参数识别
- 模板库页支持快速筛选、浏览、区分免费与付费
- 小程序端在常见移动尺寸下没有明显溢出、遮挡、对比度问题
- 长 tab 文案允许压缩字号但不应换成两行；长模板名最多展示两行；超长数值应保持右对齐并允许缩小字号，不挤压主要布局

建议验证：

- `npm --prefix frontend run build:weapp`
- 微信开发者工具预览三个页面
- 手动验证点击态、空状态、长文案换行和横向滚动表现
